### The agents (each one produces a decision, none of them act alone)

- **Class-set sizing** — shared-per-room, exams-only and own-pair models.
  Reproduces the published table variants ("devices + 2", "largest group
  + 10%", "pupil count + 10%", "largest exam group + 3"). Uses exact
  fraction arithmetic, so `100 × 1.10` is `110` and not
  `110.00000000000001`. For shared use it applies ONE non-overlapping
  attrition allowance rather than stacking the +10% buffer on top of the
  published 10–15% annual breakage figure.
- **Warranty policy** — separates warranty replacement from paid
  physical-damage repair using the internal repair-price list, while
  keeping the public-policy contradiction visible rather than resolving it
  silently.
- **Strike monitor** — bol.com strike evaluation, on-time target 93%,
  escalation to Rob at 3 strikes, VVB switch at 5 strikes. Idempotent:
  re-running it does not create duplicate approvals.
- **Stock price guard** — flags `available <= 10` (the manual says "10
  stuks of lager", so the threshold is inclusive), adds daily sales
  velocity and days-of-cover, and classifies urgency. SKU 231 is
  correctly reported **URGENT**. A 10-unit threshold is already late for
  an item selling 10 units a day.
- **Integration catalogue** — turns the 31 OSS research lanes into a
  ranked, executable backlog: 428 candidates, 23 capability gaps.
- **Scheduler** — five durable recurring jobs: Shopify price sync, UCP
  price sync, strike check, stock-price check, and a general review job.
  All five ran green with real live data (139 prices synced).

### The safety rules that matter

- **No hidden 15% school discount.** The default is 0%, and a nonzero
  value additionally requires `WISEQ_SCHOOL_DISCOUNT_CONFIRMED=true`.
  `/health` reports `school_discount_is_placeholder`. Two hardcoded 15%
  defaults were found in `WiseQOrchestrator` and `SchoolOrderAgent`
  during the audit and both were removed.
- **The 10–15% figure is annual attrition, not a discount.** The live
  site says "10–15% breakage per school year". It is now modelled as
  attrition and can never be used as a price reduction.
- **Every setup path is covered.** The 0% guard was tested against bare
  Python, against `cp .env.example .env`, and against the Compose
  defaults — because a guard that only survives one of those three is
  not a guard.
- **Remote API access fails closed.** No token configured means remote
  reads and all writes are refused. Loopback and `/health` stay open for
  development.
- **Approval gates.** Nothing consequential happens without a human:
  external messages, orders, invoices, refunds, accounting writes,
  strike escalation, price changes.
- **Missing prices block offers.** A zero price is never treated as a
  valid sell price.
- **Test mail only ever goes to `weissvanderpol@gmail.com`.**
- **Test data never rewrites live prices.** `seed_stock` seeds stock
  only; `seed_all` randomises prices and is deliberately not used by the
  live-price demo.
- **Reserved stock can never exceed on-hand.** This produced a `-3`
  available reading before it was fixed; there is regression coverage.

### Bugs found and fixed by actually running the thing

These were not theoretical; each one produced a wrong answer:

1. A copied (non-editable) package install made new source invisible —
   API routes returned 404 while the source plainly contained them. A
   regression test now pins the install mode.
2. An autouse test fixture deleted `WISEQ_API_TOKEN` from the
   environment without restoring it, silently breaking 11 tests in
   another file for a reason unrelated to the code under test.
3. The server and the smoke script used *different* default tokens, so
   every write answered 401 and the verification step failed for the
   wrong reason.
4. `reserved > on_hand` produced negative available stock.
5. The low-stock threshold was read as exclusive (`< 10`) when the manual
   says "10 stuks of lager" (`<= 10`).
6. The demo's low-stock output depended on leftover database state.
7. `1.234,56` Dutch decimal parsed as `1.23`.
8. A `sync_shopify_prices` method was referenced that does not exist.
9. The PostgreSQL cluster lived in `/tmp` and was reaped between turns.
10. `verify_all.sh` counted a *skipped* PostgreSQL suite as success.
11. The verifier could not tell "PostgreSQL is down" from "tests
    genuinely skipped". It now captures skip reasons with `pytest -rs`
    and reports `postgres UNREACHABLE (server down?)` with the start
    command, instead of a bare "4 skipped".

## Update 2026-10-30 (later)

### The human approval gate was broken and is fixed

`POST /approvals/<id>` answered **500 on every call**. The RBAC commit
`4f3cb65` dropped `decided_by` from the `ApprovalIn` request model
while the handler still read `payload.decided_by`, and mis-placed the
field into the new `TokenRotateIn` model where it did nothing.

This is the one write that clears a human gate. Every offer approval,
price change and external message was stuck behind an approval nobody
could clear. The route was never covered by the pytest suite -- only by
the shell smoke script, which is not part of the build.

Fixed in `74718e1`. The decision reason is now kept in the audit
trail, and a second decision on an already-decided approval is refused
with 409 instead of overwriting the first one.

`tests/test_api_approval_decision.py` pins the route's contract,
including an AST check that the handler never reads a field the request
model does not declare. Reintroducing the original defect fails 5 of the
8 tests.

### The delivery archive no longer loses checks

The public-site audit snapshot was gitignored, so every archive skipped
8 audit tests. The snapshot is now committed in a trimmed form (1.2 MB
-> 112 KB) that keeps only the fields the analysis reads; a test
asserts the trim is lossless.

### Approval-gate regression: fixed and protected

`POST /approvals/<id>` -- the one call that clears a human gate -- had
been answering **HTTP 500 on every call** since the RBAC work landed.
The RBAC commit dropped `decided_by` from the `ApprovalIn` request model
while the handler still read `payload.decided_by`, and re-declared the
field on the brand-new `TokenRotateIn` model where it did nothing.

Why it survived a green CI: the route was covered only by the shell
smoke script, which `pytest` does not run.

`ApprovalIn.decided_by` is restored (backwards compatible), `ApprovalIn.note`
is added, and the decision reason is now persisted to `audit_log` with a
generated `audit_id`. `tests/test_api_approval_decision.py` holds 8
regression tests, including an AST-based check that the handler never
reads a field the request model does not declare. The test was proven to
bite: reintroducing the original defect produced 5 failures.

### Environment note: PostgreSQL must be started detached

The scratch PostgreSQL kept receiving a clean "smart shutdown request"
partway through verification runs, which failed the PostgreSQL step with
"connection refused" for reasons unrelated to the code. The server had
been started as a child of a transient shell, and the sandbox death
supervisor reaps that process group when the session ends. Starting it in
its own session (`setsid`) fixes it. The reusable helper is
`scripts/start_pg.sh` in the `wiseq-public-data-audit` skill.
